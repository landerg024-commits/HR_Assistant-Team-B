# AI HR Assistant Developer Guide

## Layer flow

```text
UI Page
  ↓
Service
  ↓
Repository
  ↓
SQLAlchemy Model / Database
```

### UI

The UI displays data and collects user input. It should not contain SQL
queries or complex business rules.

### Service

The service validates business rules and coordinates multiple repositories.

### Repository

The repository owns database queries and CRUD operations.

### Model

The model defines database tables, columns, relationships, and constraints.

### Schema

Pydantic schemas validate data before it reaches the service layer.

## Company isolation

Most HR records contain `company_id`.

Queries must include the current company ID so one company cannot read
another company's users, employees, departments, roles, leave records, or
documents.

## Employee identity

Do not use the employee's full name as a unique identifier.

Use:

```text
company_id + employee_number
```

Multiple employees may legally share the same full name.

## Passwords

Never store or log a plain-text password.

The application stores only the Argon2 hash generated by:

```text
authentication/password_manager.py
```

## Initial data

The seed script is safe to run multiple times:

```powershell
python scripts\create_initial_data.py
```

It checks existing records before creating:

- Company
- System roles
- Initial administrator
- Administrator employee profile

## Debugging order

When a feature fails, check the layers in this order:

1. `.env` and `config/settings.py`
2. Database connection and tables
3. Model relationships and constraints
4. Repository query
5. Service validation
6. UI page or component
7. Streamlit session state

Security rules:

## Signed-cookie refresh authentication

```text

  ↓

  ↓
```

## Chat Assistant terminal diagnostics (v0.8.8.217)

`modules/smart_ai/terminal_trace.py` provides request-local terminal-only
retrieval diagnostics. `SmartPortalAssistant` creates one trace per request and
passes it into `HybridRetriever`; no trace object is stored in Streamlit Session
State, returned in `HRAssistantResponse`, or rendered by either Chat page.

When enabled, the trace exposes bounded, already-authorized evidence only and
prints to stderr. It includes file-stage and chunk-stage BM25/vector/hybrid
scores, selected files/chunks, final Qwen evidence, deterministic/router output,
model timing/retry events, raw Qwen output, and the final normalized answer.

Keep this diagnostic path side-effect free: it must never change ranking,
permission scoping, prompt content, retry count, or UI state. Disable it with
`SMART_AI_TERMINAL_DEBUG_ENABLED=false` when console traces are not needed.

## Chat Assistant terminal candidate-answer diagnostics (v0.8.8.218)

v0.8.8.218 extends the existing terminal-only trace with source-labeled candidate answer excerpts. Set `SMART_AI_TERMINAL_DEBUG_CANDIDATE_ANSWER_CHARS` to bound each candidate excerpt. Candidate diagnostics are observational only: they are not stored in Session State, returned in `HRAssistantResponse`, or used as an extra ranking/generation signal. The trace also prints router and Qwen answer options plus the selected final answer path for easier FAIL/PARTIAL diagnosis.

## v8.8.222 adaptive chunking / evidence-gate diagnostic contract

- Base: exact v8.8.221 Qdrant checkpoint.
- Policy and Company Form/Documents content uses adaptive structure-aware chunking only; structured live HR records remain deterministic and must not be flattened into document chunks.
- Preserve a complete semantic section when it fits inside the configured hard maximum. Split oversized sections on sentence/row boundaries, then clause boundaries, and use fixed-word windows only as a final safety fallback.
- Adaptive overlap applies only between fragments of the same split section. Intact semantic sections carry no artificial overlap.
- Every file-backed chunk must retain `chunk_word_count`, `chunk_overlap_words`, `chunk_boundary_reason`, `section_chunk_index`, `section_chunk_total`, continuation flags, and the existing file/title/section/page/permission metadata.
- Neighbor expansion is conditional: add adjacent context only when the seed belongs to a section that was actually split. Intact sections should not consume a neighbor slot.
- The request-local full log includes privacy-safe per-file `CHUNK DIAGNOSTICS` and a `CHUNKING BATCH SUMMARY`. Full raw chunk text remains disabled by default (`SMART_AI_CHUNK_DIAGNOSTICS_FULL_TEXT=false`).
- Exact-fact document/policy requests use the deterministic evidence gate before generation. Topic coverage alone is insufficient for amount, count/duration, date/time, consequence, eligibility, and procedure profiles; an answer-bearing evidence cue is also required.
- Never replace this evidence gate with an additional LLM/judge call. The gate must stay deterministic so it cannot introduce another hallucination path or extra model latency.
- Qdrant, BM25, embeddings, optional CrossEncoder reranking, tenant/user/role filters, deterministic HR services, and LLM routing remain otherwise unchanged.


## v8.8.223 source-aware routing safety contract

- Do not encode company benefits, tenure thresholds, entitlements, or policy
  outcomes in the router. Routing logic may classify generic linguistic request
  shape only.
- Employee aggregate/list handlers must require an explicit leading collection,
  count, group, or chart request. Embedded relative-clause words such as `who`
  are not collection commands.
- A deterministic aggregate handler must decline a request when meaningful
  conditions remain that the handler did not apply. Never silently ignore an
  unsupported filter.
- Specific policy questions must not be reduced to policy-library summaries.
- `employee_aggregate` is still a never-enhance intent only when its output shape
  is compatible with the user's leading request clause. Incompatible results
  recover to authorized evidence-gated retrieval.
- Active `CompanyBenefit` rows are shared company knowledge for both portals;
  archived benefit rows must never be indexed as current evidence.
- Security/tenant isolation and all existing live-record authority rules remain
  unchanged.

## v8.8.224 vector/latency/grounding contract

- `sentence-transformers` is a required runtime dependency for the configured
  local E5 embedding model. Never silently ship Qdrant code without the local
  embedding runtime declared in `requirements.txt`.
- Qdrant failures remain non-fatal because BM25 is the safe fallback, but every
  request trace must expose a non-sensitive vector status. Do not swallow a
  missing dependency/model/query error as an unexplained `0 results` state.
- Authorized snapshot signatures must be independent of document iteration
  order. Reuse a persisted exact-scope Qdrant snapshot after process restart
  when it already contains the full authorized document count.
- Encode documents in bounded batches and upsert Qdrant points in bounded
  batches to avoid unnecessary Windows RAM spikes during large re-indexes.
- The grounded extractive fast path is selection-only: every returned sentence
  or row must come verbatim from authorized evidence. It may format selected
  units into bullets/steps but must not synthesize new HR facts.
- Use the fast path only after the existing relevance/evidence gate accepts the
  request, and only for direct fact/list/procedure profiles. Keep YES/NO,
  follow-up, comparison, ambiguity, and synthesis-heavy requests on the normal
  grounded Qwen path.
- Preserve explicit source qualifiers and requested numeric/service milestones;
  do not select a sentence that states only a different milestone than the one
  explicitly asked about.
- The source-aware router, adaptive chunker, tenant/role/user permissions, and
  deterministic live HR authority remain unchanged.

## v8.8.226 — Authenticated unified QA session log contract

This is a logging-only continuation of v8.8.225 (local Qdrant/Ollama branch).
UI question handlers mint one high-entropy ID into per-browser-tab Streamlit
Session State keyed by authenticated company + user and portal. New Conversation
rotates it. Only calls with valid ID, company/user and `admin` / `employee`
scopes enter session mode; legacy integrations remain request-log compatible.

`TerminalChatTrace.create()` uses separate company/portal/user directories with
non-plaintext ID labels and one `QA_Session_*.log` file per session. The
complete per-request buffer is appended atomically with a thread lock and a
local OS file lock (POSIX `flock`, Windows `msvcrt.locking`). Individual traces
keep Trace IDs, per-request summary, response time and a `SESSION CHECKPOINT`
marker; their order is completion order when concurrent. Streamlit stderr
remains compact; the file contains the full forensic stages. Preflight
connection failures use the same trace writer. Files are created with
restricted permissions when the OS supports POSIX modes; deployment must
restrict account and directory access on Windows separately. Never treat
hash-based path labels as authorization. Authentication/tenant/RBAC checks
remain upstream and are unchanged.

Keep production debug logging disabled if raw content is sensitive. Avoid
indefinite QA log retention (set access and cleanup policies operationally).
A process kill mid-generation may leave an in-flight request incomplete; other
completed question blocks remain intact.

Switch: `SMART_AI_TERMINAL_DEBUG_SESSION_LOGGING_ENABLED=true` (defaults true).
For legacy request-local files set false. `SMART_AI_TERMINAL_DEBUG_LOG_ENABLED`
continues to control whether evidence is persisted at all.


## v8.8.227 — Answer-target contract and latency trace points

`modules/smart_ai/portal_ai.py` retains role-scoped retrieval and RRF.
`_direct_action_target` detects generic who/what action predicates; `_grounded_extractive_answer`
uses sentence and same-chunk preceding-section context for *ranking* and rejects
unrequested conditional fallback sentences in default-first requests. Extraction
copies the unmodified chosen evidence sentence, never synthesizing HR facts. If
no requested predicate is in the selected answer, it returns an empty fast-path
result and the existing evidence-gated generator handles it. `HR_ASSISTANT_RULES`
adds answer-target fidelity rules for that generator.

Timing is recorded in the same per-session QA trace without duplicate per-question
files: knowledge build, file/chunk BM25, vector (model setup, index, query embed,
Qdrant query), reranking, final hybrid retrieval, fast-path validation, and
existing end-to-end/Ollama timers. Do not expose forensic logs to employees;
logs may contain company policy passages and sensitive HR record excerpts.

## v8.8.228 — Compound action evidence and embedding lifecycle

`_compound_direct_fact_evidence` validates coordinated answer objects against
nearby generic action predicates. For an implicit/anaphoric payment rule, only
an immediately adjacent prior sentence with an expense-object anchor can be
joined (verbatim and from the same document chunk). An unrelated “no X
available” condition is not an action-supported answer for X. Incomplete
compound answers bypass extractive selection and use existing evidence-gated
synthesis; no application-specific policy rules are embedded.

`QdrantRetriever._embedding_models` shares the immutable SentenceTransformer
model instance by model name within a process, using `_embedding_load_lock` for
constructor synchronization and `_embedding_encode_locks` for inference
synchronization. The retriever's actual documents, query embeddings, indexes,
client Qdrant searches, and access partitions are NOT shared via this cache;
Qdrant `retrieval_scope` filtering and existing company/user/role checks remain.
Model instances remain process-resident; restart Streamlit if changing model
settings or if memory reclamation is required. Validate with Windows Qdrant
logs (`model_cache`, `model_setup_s`) and real concurrent Admin/Employee tests.

## v8.8.230 — Evidence-linked compound extraction, recipient coverage, warning cleanup

Changes from v8.8.229 are restricted to `modules/smart_ai/portal_ai.py`,
`scripts/run_with_terminal_log.py`, Chat Assistant settings, version markers,
these docs and focused regression tests. All deterministic HR workflows,
security/permission checks, Qdrant retrieval, chunking, local embeddings and
model choice remain unchanged.

* `_explicit_notification_recipients` parses only named direct objects after a
  notification predicate, stopping before the event clause (about/regarding).
  The fast path requires all those literal phrases in a candidate clause;
  otherwise it declines to synthesize an incomplete list.
* `_compound_direct_fact_evidence` groups candidate clauses by authorized
  `file_key`, company, source type and version, never by a bare file name when
  a stable file key exists. It validates a requested action for each coordinated
  object. It accepts a same-chunk immediate preceding transportation-expense
  antecedent for generic payment statements. It never attributes a payment
  merely because a resource was unavailable in an unrelated hotel condition.
* `_grounded_extractive_answer` retains those anaphoric payment candidates even
  when their clause omits the full requested object name. This is not an
  additional knowledge source, only a more faithful use of already authorized
  adjacent evidence.
* A failed **direct_fact** fast-path attempt gets **one compact standard**
  Qwen generation, with `grounded_direct_fact_ollama_timeout_seconds` (30s
  default, hard clamp 5–60s), no timeout retry; failed requests use the
  undetermined response, not unverified router excerpts. Other profiles and
  intentional synthesis are unaffected. The observed 180s/90s timeout on a
  simple flight-policy fact must not recur on this new branch.
* The dedicated runtime-log launcher disables Streamlit file-watching by
  default via `STREAMLIT_SERVER_FILE_WATCHER_TYPE=none`; this addresses watcher
  errors while examining optional Transformers modules that require
  `torchvision`. The viewer can still open and use the app; automatic hot reload

## v8.8.242 — Groq / Local / Hybrid switch (no UI)

You can keep the current v8.8.241 running while testing this separate release.
Provider selection changes **only generation requests that reach the optional LLM**; it does not replace the deterministic HR answers, local Qdrant, embeddings, CrossEncoder, policy scope, company/role access, or the extractive fast path. Consequently, questions answered entirely by existing grounded/deterministic paths do not need to call either model.

Edit your **existing private `.env`** in the project root (do not overwrite it with the sample):

```dotenv
# Change this ONE value to select behavior: local / groq / hybrid
SMART_AI_LLM_MODE=local

# Groq only if cloud use is approved by your company
SMART_AI_GROQ_API_KEY=replace_with_your_actual_key
SMART_AI_GROQ_MODEL=qwen/qwen3.8-27b
SMART_AI_GROQ_TIMEOUT_SECONDS=25

# Existing local Ollama model/settings remain unchanged
SMART_AI_OLLAMA_BASE_URL=http://localhost:11434
SMART_AI_OLLAMA_MODEL=qwen2.5:7b
```

| `SMART_AI_LLM_MODE` | Behavior |
| --- | --- |
| `local` (**default**) | Ollama only; does not contact Groq, even if Groq API key is present. |
| `groq` | Groq only; never calls Ollama, even if Groq is unavailable. The system keeps only any supported deterministic answer. |
| `hybrid` | Groq is attempted first; on missing key, timeout, HTTP error, network error, or empty answer it falls back to the existing local Ollama generation path. Does **not** run both in parallel. |

`GROQ_API_KEY=` (without prefix) is accepted as an alternative to `SMART_AI_GROQ_API_KEY=`, but prefer the prefixed setting. API key is loaded as a secret; it is neither displayed in settings `repr` nor written to provider traces. Restart the Streamlit process (and restart the Terminal QA runner) after changing `.env`, since application settings are cached in each Python process. Only change `.env` for version v8.8.242, not v8.8.241.

**Cloud privacy notice:** Groq-only and Hybrid transmit the question and **authorized company evidence included in the grounded prompt** to an external provider for inference. Confirm the company's HR data handling/contractual requirements before opting into cloud use. This option does not alter local data indexing, but the generated cloud requests do leave the local PC. Do not place your real Groq API key in screenshots or logs shared publicly.

**Model availability:** `qwen/qwen3.8-27b` is listed as a Groq Preview model in October 2026. Check account model permissions, rate limits and pricing. If unavailable, change `SMART_AI_GROQ_MODEL=` to an active model ID accessible to your account. No SDK installation is required; the integration uses Python's standard-library HTTPS client.
