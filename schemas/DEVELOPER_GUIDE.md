# AI HR Assistant Developer Guide

## Layer flow

```text
UI Page
  ↓
Service
  ↓
Repository
  ↓
SQLAlchemy Model / Database
```

### UI

The UI displays data and collects user input. It should not contain SQL
queries or complex business rules.

### Service

The service validates business rules and coordinates multiple repositories.

### Repository

The repository owns database queries and CRUD operations.

### Model

The model defines database tables, columns, relationships, and constraints.

### Schema

Pydantic schemas validate data before it reaches the service layer.

## Company isolation

Most HR records contain `company_id`.

Queries must include the current company ID so one company cannot read
another company's users, employees, departments, roles, leave records, or
documents.

## Employee identity

Do not use the employee's full name as a unique identifier.

Use:

```text
company_id + employee_number
```

Multiple employees may legally share the same full name.

## Passwords

Never store or log a plain-text password.

The application stores only the Argon2 hash generated by:

```text
authentication/password_manager.py
```

## Initial data

The seed script is safe to run multiple times:

```powershell
python scripts\create_initial_data.py
```

It checks existing records before creating:

- Company
- System roles
- Initial administrator
- Administrator employee profile

## Debugging order

When a feature fails, check the layers in this order:

1. `.env` and `config/settings.py`
2. Database connection and tables
3. Model relationships and constraints
4. Repository query
5. Service validation
6. UI page or component
7. Streamlit session state

## Authentication flow

```text
Login Form
  ↓
Pydantic LoginRequest
  ↓
AuthService
  ↓
CompanyRepository + UserRepository
  ↓
Argon2 verification
  ↓
AuthenticatedUser
  ↓
AuthSessionManager
  ↓
Admin or Employee Layout
```

Security rules:

- Login is always scoped by company code.
- Username or email is searched only inside that company.
- Passwords and hashes never enter Streamlit session state.
- Inactive companies, users, and roles cannot log in.
- Initial accounts must replace the temporary password.
- Admin layouts repeat authorization checks for defense in depth.
